## Task 1: Linux File Permissions Audit (25 marks)

**Objective:** Enumerate and analyse file permissions on a Linux system to identify misconfigurations.

### Setup
Use your Ubuntu VM (or any Linux system — WSL on Windows is acceptable for this task).

### Steps

**1a. Find all SUID binaries on the system:**
```bash
find / -perm -4000 -type f 2>/dev/null | sort
```
List the output. For any SUID binary not in `/bin` or `/usr/bin`, explain why it may be a risk.

**1b. Audit home directory permissions:**
```bash
ls -la /home/
ls -la /home/<your-username>/
```
Are any home directories world-readable (permissions include `r` for others)? What risk does this create?

**1c. Check /etc/shadow permissions:**
```bash
ls -la /etc/shadow
ls -la /etc/passwd
```
Document the exact permissions shown. What would happen if `/etc/shadow` were world-readable?

**1d. Create a privilege misconfiguration and fix it:**
```bash
# Create a test file
echo "secret data" > /tmp/testfile.txt
chmod 777 /tmp/testfile.txt
# Document the permissions
ls -la /tmp/testfile.txt
# Fix to appropriate permissions
chmod 600 /tmp/testfile.txt
ls -la /tmp/testfile.txt
```
Screenshot both before and after `ls -la` outputs. Explain why 600 is appropriate here.

| Home directory findings with risk explained | 6 |

## Task 2: Windows Event Log Investigation (25 marks)

**Objective:** Locate and interpret Windows Security Event Log entries to identify suspicious activity.

### Setup
Use a Windows machine with access to Event Viewer. You will simulate an "incident" and then investigate it.

### Steps

**2a. Simulate failed logon attempts:**
Open a command prompt and run (this will fail intentionally — use a wrong password):
```
runas /user:FakeUser cmd
```
Press Enter without a password, or type a wrong password, 3 times.

**2b. Open Event Viewer and find your events:**
- Press Win+R → `eventvwr.msc` → Windows Logs → Security
- Filter for Event ID **4625** (failed logon)
- Find the events generated by your test

Document: timestamp, account name, logon type, failure reason, source IP (if shown).

**2c. Investigate process creation:**
- Filter Security log for Event ID **4688** (new process created)
- Find the most recent `cmd.exe` or `powershell.exe` execution
- Document: what process created it (Parent Process Name), the full command line (if audit policy is enabled)

**2d. PowerShell investigation:**
```powershell

Get-LocalGroupMember -Group "Administrators"
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625} -MaxEvents 5 |
    Format-List TimeCreated, Message
```

## Task 3: Linux Log Analysis with grep & awk (25 marks)

**Objective:** Extract actionable intelligence from authentication logs using Linux CLI tools.

### Setup
On your Linux VM: `sudo cat /var/log/auth.log` (Ubuntu) or `/var/log/secure` (CentOS/RHEL)

If your system has no SSH activity, generate some:
```bash
# Install and start SSH service if needed
sudo apt install openssh-server && sudo systemctl start ssh
# Attempt some bad logins from another terminal:
ssh wronguser@localhost    # enter wrong password 3 times
```

### Tasks

**3a.** Extract all failed SSH login attempts with their timestamps:
```bash
grep "Failed password" /var/log/auth.log | tail -20
```

**3b.** Count failed attempts by username:
```bash
grep "Failed password" /var/log/auth.log | \
  awk '{print $(NF-5)}' | sort | uniq -c | sort -rn
```

**3c.** Extract all IPs that attempted to log in:
```bash
grep "Failed password" /var/log/auth.log | \
  grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' | sort | uniq -c | sort -rn
```

**3d.** Find successful logins for the last 7 days:
```bash
grep "Accepted password\|Accepted publickey" /var/log/auth.log | tail -10
last | head -20
```

**Written analysis (required):** Based on your log output, write a 5–8 sentence "security incident summary" as if you were writing a brief for a manager. Include: what happened, which usernames/IPs were involved, likely intent, and what you recommend.

### Rubric
| Criteria | Marks |
|---------|-------|
| All 4 commands run with output documented | 12 |
| grep/awk syntax explained in your own words | 6 |
| Incident summary written clearly | 7 |

## Task 4: Build a 2-VM Homelab (25 marks)

**Objective:** Configure VirtualBox with two VMs on an isolated network, verify connectivity, and test a basic SSH connection.

### Steps

**4a. Create two VMs in VirtualBox:**
- VM1: Ubuntu Server 22.04 LTS (download from ubuntu.com/server)
- VM2: Kali Linux (download from kali.org/get-kali) OR a second Ubuntu Desktop
- Allocate: 2 GB RAM and 20 GB disk each

**4b. Configure networking:**
Set both VMs to **Internal Network** adapter in VirtualBox (Settings → Network → Adapter 1 → Internal Network, name it `homelab`).

Assign static IPs inside each VM:
- VM1 (Ubuntu Server): `192.168.99.10/24`
- VM2 (Kali): `192.168.99.20/24`

On Ubuntu: edit `/etc/netplan/00-installer-config.yaml`
On Kali: use the Network Manager GUI or `/etc/network/interfaces`

**4c. Test connectivity:**
From VM2: `ping -c 4 192.168.99.10`
From VM1: `ping -c 4 192.168.99.20`

**4d. Install and connect via SSH:**
On VM1: `sudo apt install openssh-server && sudo systemctl enable ssh`
From VM2: `ssh ubuntu@192.168.99.10`

### Deliverables
- Screenshot of both VMs running simultaneously (show VirtualBox VM manager)
- Screenshot of successful ping between VMs
- Screenshot of successful SSH connection from VM2 to VM1 (show the terminal prompt change)

| Criteria | Marks |
|---------|-------|
| Both VMs created and running | 5 |
| Internal Network configured, static IPs set | 8 |
| Successful bi-directional ping proven | 6 |
