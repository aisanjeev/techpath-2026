Watch how a browser request to https://example.com travels through the OSI stack.

1

Layer 7 — Application: HTTP Request

Your browser prepares GET / HTTP/2 with headers: Host, User-Agent, Accept, Cookie. This is the payload — everything else wraps around it.

2

Layer 6 — Presentation: TLS Encryption

TLS encrypts the HTTP request using the session key negotiated during the handshake. The plaintext GET / becomes ciphertext. The server's identity was already verified via PKI.

3

Layer 5 — Session: Connection Management

The TLS session context is maintained here — session tickets allow resumption without a full handshake. HTTP/2 multiplexes multiple streams over one connection.

4

Layer 4 — Transport: TCP Segment

TCP adds source port (ephemeral, e.g., 52341) and destination port (443), sequence number, and ACK. Ensures ordered, reliable delivery to the correct service.

5

Layer 3 — Network: IP Packet

IP header added: source IP 192.168.1.5, destination IP 93.184.216.34, TTL=64, protocol=6 (TCP). The router reads this header to decide the next hop.

6

Layer 2 — Data Link: Ethernet Frame

Wrapped in an Ethernet frame: source MAC (your NIC), destination MAC (your router's MAC from ARP cache). FCS checksum appended for error detection on this hop only.

7

Layer 1 — Physical: Bits on the Wire

Frame converted to electrical signals (copper), light pulses (fiber), or radio waves (Wi-Fi). Travels to your router. Router strips Layer 2, makes routing decision, re-frames with new MACs, transmits onward.

8

Server — Decapsulation (Reverse)

Server's NIC receives bits → assembles frame → strips Ethernet → strips IP → strips TCP → strips TLS → delivers plaintext HTTP to nginx/Apache. Response travels back through the same stack in reverse.
