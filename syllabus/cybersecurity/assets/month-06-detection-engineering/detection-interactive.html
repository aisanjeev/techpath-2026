Click each level to learn how much pain blocking that indicator causes the attacker

🏆TTPs (Tactics, Techniques, Procedures)Tough!
The highest level. TTPs describe HOW attackers operate — their methodology, tools they habitually use, and the order they do things.

If you can detect and block TTPs, the attacker must fundamentally change how they operate — retrain their team, rewrite their tooling, rethink their approach. This is massively disruptive and expensive for them.

Examples: "Spear phishing with macro-enabled Office docs as initial access", "Kerberoasting for credential access", "Living-off-the-land with LOLBins"

How to detect: Behavioral analytics, UEBA, MITRE ATT&CK-mapped Sigma rules that detect patterns (not just exact signatures).
🔧ToolsChallenging
Specific attacker tools: Mimikatz, Cobalt Strike, Metasploit, custom malware. If you block their tools (AV detection, YARA rules on specific binaries), the attacker must find or build a replacement.

This takes days to weeks and is genuinely painful — especially if they use custom tools they invested significant effort in.

How to detect: YARA rules on tool-specific byte patterns, heuristic AV rules, detecting tool behaviour (not just the binary hash).
🌐Network / Host ArtefactsAnnoying
Artefacts left by attacker activity: specific registry keys malware creates, unusual process parent-child relationships, specific HTTP User-Agent strings, C2 beaconing patterns.

Changing these requires modifying malware source code — time-consuming but doable for determined attackers.

How to detect: Behavioural EDR rules, Sysmon detection of specific artefacts, SIEM correlation rules.
🌍Domain NamesSimple
C2 domains and phishing domains used by the attacker. Blocking these forces the attacker to register new domains — a few minutes and a few dollars.

However, blocking domains is still valuable because it disrupts current campaigns while the attacker pivots.

How to detect/block: DNS RPZ (Response Policy Zones), threat intel feeds, domain reputation blocking. Detect fast-flux and DGA (Domain Generation Algorithm) patterns.
🔢IP AddressesEasy for them
C2 server IP addresses. Blocking an IP is trivially easy to evade — the attacker moves to a new VPS/bulletproof host for ~$5. They can have hundreds of IPs ready to rotate.

Still valuable for current campaigns, but don't rely on IP blocking as a primary defence.

How to block: Firewall rules, SIEM correlation, threat intel feeds with IP blocklists (AbuseIPDB, Emerging Threats).
🔑Hash ValuesTrivial
Exact file hashes (MD5, SHA-256) of malware binaries. Blocking specific hashes is the weakest indicator — adding a single null byte to a file changes its hash completely. Takes the attacker seconds to evade.

Hash-based detection is still useful for known-bad IOC lookups (VirusTotal), but should never be your PRIMARY detection method.

How to use: Hash-based lookup on file creation events, VirusTotal integration in SOAR playbooks. Supplement with behaviour-based detection.
Higher = more pain for the attacker when you block it. Aim for TTPs and Tools, not just hashes.
