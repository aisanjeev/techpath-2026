Common cloud attack paths. Click each to see the step-by-step exploitation chain and defences.

🪣Exposed S3 Bucket → Data BreachCRITICAL
OSINT / Shodan scan
→
Find s3://company-backups public
→
aws s3 ls s3://company-backups
→
Download entire bucket
→
Find DB dumps, API keys, PII
Defences: Enable S3 Block Public Access at account level. Use AWS Config rule 's3-bucket-public-read-prohibited'. Enable GuardDuty S3 Protection. Scan for public buckets with Prowler regularly.
🔑Leaked AWS Keys → Full Account TakeoverCRITICAL
GitHub scraper finds AWS keys in .env file
→
aws sts get-caller-identity (verify working)
→
Enumerate permissions (CloudMapper/Pacu)
→
Escalate to admin via iam:CreatePolicyVersion
→
Launch crypto miners, exfil data, pivot
Defences: Use GitHub secret scanning. Enable GuardDuty (detects anomalous API calls). Use IAM roles instead of access keys. Rotate keys every 90 days. Set up CloudTrail alerts for unusual IAM activity.
⚡SSRF → AWS Metadata → Role CredentialsHIGH
Find SSRF vuln in web app
→
Fetch http://169.254.169.254/latest/meta-data/iam/security-credentials/
→
Get temporary role credentials (AccessKey+Secret+Token)
→
Use credentials from attacker's machine
→
Pivot to other AWS services
Defences: Enable IMDSv2 (requires PUT token before GET — blocks simple SSRF). Fix the SSRF vulnerability. Limit EC2 role permissions to minimum needed. Use GuardDuty to detect unusual API calls from EC2.
📦Malicious Container Image → Cluster CompromiseHIGH
Attacker pushes malicious image to public registry
→
Developer pulls "official-looking" image
→
Container deployed with host network access
→
Escape to host node
→
Access cloud metadata → IAM role → AWS APIs
Defences: Scan images with Trivy before deployment. Use private registries with signing. Enforce Pod Security Standards (restricted). Use securityContext to run as non-root. Enable Falco for runtime threat detection.
🏗️Terraform Misconfiguration → Exposed DBMEDIUM
RDS created with publicly_accessible = true
→
Security group allows 0.0.0.0/0 on port 5432
→
Shodan finds the exposed PostgreSQL endpoint
→
Brute force weak DB password
→
Full database access
Defences: Run Checkov on all Terraform before apply (check CKV_AWS_17 for RDS public access). Never allow 0.0.0.0/0 to DB ports. Put RDS in private subnet. Use AWS Secrets Manager for DB passwords. Enable RDS encryption.
